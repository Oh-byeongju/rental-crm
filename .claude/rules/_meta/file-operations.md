# 파일/폴더 작업 시 영향 처리 룰

> 디렉토리 이동, 파일명 수정, 파일 이동·삭제 등 구조 변경 작업 시 따른다.

---

## 원칙

> **작업이 다른 파일에 영향(경로 참조 등) 을 주는 경우, 즉시 수정한다.**
> 사용자에게 묻지 않고 진행한다.

## 적용 시점

- 디렉토리 이동 / 이름 변경
- 파일 이동 / 이름 변경
- 파일 삭제 (다른 파일이 해당 파일을 참조하는 경우)

## 절차

1. **영향 범위 grep**
   - 옛 경로·옛 파일명을 참조하는 모든 파일 식별
   - 한글 경로면 ripgrep 한계로 `bash grep -rl` 활용
2. **모든 참조처를 새 경로·이름으로 일괄 수정**
   - `Edit replace_all` 또는 도메인 단위로 묶어 처리
3. **결과 보고**
   - 이동된 파일/폴더 + 갱신된 참조처 목록

## 예외

- 영향 범위가 매우 크거나 (예: 50개 이상 파일) 작업 정합성이 의심스러우면 사용자에게 확인 후 진행
- 사용자가 명시적으로 "참조 그대로 두라" 고 지시한 경우만 그 결정을 따름

## 안티패턴

### ❌ 묻고 멈춤

```
"옛 경로를 가리키는 파일 N개 있어요. 수정할까요?"
```

→ 묻지 않는다. 즉시 수정한다.

### ❌ 부분 수정

영향처 일부만 수정하고 나머지는 미수정 상태로 둠 → 코드베이스 정합성 깨짐.
→ 발견된 영향처는 **모두** 같은 작업 사이클 안에서 처리.
