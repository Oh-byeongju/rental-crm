## 5. 기술 시나리오

### Chapter 1. 대량 쓰기 — bulk INSERT

**실무 배경**
경남에너지 마이그레이션(JDK 6→8) 과정에서 SAP EAI 연계로 매일 수납 데이터 3~5만 건을 INSERT하는 배치 운영.
이 시나리오를 장비 렌탈 월 청구 생성 배치로 재현.

**데이터 규모**
- 고객 마스터: 약 50만 건
- 월 청구 생성 처리량: 약 3~5만 건

**기술 포인트**
- 건별 INSERT vs bulk INSERT 성능 비교 (직접 측정)
- Oracle MERGE 멱등성 설계 (재실행 시 중복 청구 방지)

**구현 순서**
- [ ] 테이블 설계 (고객 마스터, 계약, 청구, 배치 실행 이력)
- [ ] 가라 데이터 생성 (50만 건)
- [ ] 건별 INSERT 구현 → 5만 건 성능 측정
- [ ] bulk INSERT 전환 → 동일 조건 재측정 → 수치 비교
- [ ] 멱등성 설계 (MERGE 활용)
- [ ] 트러블슈팅 기록

---

### Chapter 2. 대량 읽기 — 쿼리 튜닝 + 엑셀 다운로드

**실무 배경**
부산상수도사업본부 자산관리시스템 유지보수 중 수십만 건 연계 데이터 조회 + 엑셀 다운로드 성능 문제 발생.
이 시나리오를 렌탈 청구 이력 조회 + 미납 현황 엑셀 다운로드로 재현.

**데이터 규모**
- 청구 이력 연계 데이터: 수십만 건
- 엑셀 다운로드 단건 요청 시 전체 조회

**기술 포인트**
- 서브쿼리 → JOIN으로 전환 (실행계획 비교)
- 조인 순서 최적화
- 엑셀 다운로드 시 대량 데이터 스트리밍 처리

**구현 순서**
- [ ] 테이블 설계 (청구 이력, 계약, 고객 조인 구조)
- [ ] 가라 데이터 생성 (수십만 건)
- [ ] 서브쿼리 기반 쿼리 작성 → 성능 측정
- [ ] JOIN 구조로 전환 → 재측정 → 수치 비교
- [ ] 실행계획(EXPLAIN PLAN) 비교 기록
- [ ] 트러블슈팅 기록

### Chapter 3. Kafka 이벤트 파이프라인

**실무 배경**
경북연구원 신규 구축 중 A10 연계 경험을 바탕으로 Kafka 직접 구축 예정.
해당 경험을 렌탈 청구 이벤트 파이프라인에 적용.

**이벤트 흐름**
```
청구 생성 이벤트 → 알림 발송
수납 완료 이벤트 → 연체 상태 해제 / 다음 달 청구 대기
미납 이벤트      → 연체 처리 / 해지 플로우 진입
```

**기술 포인트**
- Producer / Consumer 양방향 토픽 설계
- 이벤트 순서 보장 / 재처리 설계
- A10 연계 구조 경험을 Kafka 기반으로 재현한 근거 설명 가능
