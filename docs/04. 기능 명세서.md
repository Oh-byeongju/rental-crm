# 기능 명세서

---

## 0. 공통 정의

### 0-1. 상태 코드

**계약상태 (CONTRACT_STATUS)**
| 코드 | 값 | 설명 |
|---|---|---|
| ACTIVE | 정상 | 청구 생성 배치 대상 |
| SUSPENDED | 일시정지 | 청구 생성 제외, 수납 가능 |
| TERMINATED | 해지 | 청구 생성 제외, 수납 불가 |

**청구상태 (BILLING_STATUS)**
| 코드 | 값 | 설명 |
|---|---|---|
| UNPAID | 미납 | 납기일 이전 미수납 |
| OVERDUE | 연체 | 납기일 초과 미수납 |
| PAID | 수납완료 | 수납 처리 완료 |
| CANCELLED | 취소 | 계약 해지 등으로 취소 |

**수납방법 (PAYMENT_METHOD)**
| 코드 | 값 |
|---|---|
| CARD | 카드 |
| BANK | 계좌이체 |
| CASH | 현금 |
| TOSS | 토스페이먼츠 |

**방문유형 (VISIT_TYPE)**
| 코드 | 값 |
|---|---|
| INSTALL | 설치 |
| CHECK | 점검 |
| COLLECT | 수거 |

### 0-2. 상태 전이

**계약 상태 전이**
```
등록
  └─▶ ACTIVE
        ├─▶ SUSPENDED (일시정지)
        │     └─▶ ACTIVE (재개)
        └─▶ TERMINATED (해지) — 종단 상태
```

**청구 상태 전이**
```
청구 생성
  └─▶ UNPAID
        ├─▶ PAID (수납 처리)
        ├─▶ OVERDUE (납기일 초과 배치)
        │     └─▶ PAID (연체 상태에서 수납)
        └─▶ CANCELLED (계약 해지)
```

### 0-3. Kafka 이벤트 명세

| 토픽 | 발행 시점 | 페이로드 | Consumer 처리 |
|---|---|---|---|
| `rental.billing.created` | 월 청구 배치 완료 | `{ billingMonth, count }` | 알림 INSERT |
| `rental.payment.completed` | 수납 처리 완료 | `{ billingId, customerId, amount }` | 연체 해제 + 알림 INSERT |
| `rental.payment.overdue` | 납기 초과 배치 | `{ billingId, customerId, overdueDays }` | 연체 상태 변경 + 알림 INSERT |
| `rental.visit.assigned` | 방문 배정 완료 | `{ visitId, engineerId, contractId }` | 알림 INSERT |

## 1. 공통 관리

### 1-1. 공통코드 관리

**처리 흐름**
```
코드 그룹 목록 → 그룹 선택 → 하위 코드 목록
                              └─▶ 코드 등록/수정/삭제
```

**유효성 검사**
- 코드 그룹 키: 영문 대문자 + 언더스코어만 허용
- 코드값: 그룹 내 중복 불가
- 사용 중인 코드 삭제 불가 (참조 데이터 존재 시)

**기본 코드 그룹**
| 그룹코드 | 그룹명 |
|---|---|
| EQUIPMENT_TYPE | 장비유형 |
| CONTRACT_STATUS | 계약상태 |
| BILLING_STATUS | 청구상태 |
| PAYMENT_METHOD | 수납방법 |
| VISIT_TYPE | 방문유형 |

### 1-2. 관리자 계정 관리

**유효성 검사**
- 이메일 형식 검증 + 중복 불가
- 비밀번호: 8자 이상, 영문+숫자+특수문자 조합
- 마지막 관리자 계정 비활성화 불가

### 1-3. 권한 관리

**처리 흐름**
```
역할 생성 → 메뉴별 접근 권한 설정 → 관리자에 역할 부여
```

**예외 처리**
- SUPER_ADMIN 역할 수정/삭제 불가

## 2. 회원(고객) 관리

### 2-1. 고객 목록 조회

**검색 조건**: 고객명(LIKE) / 연락처(LIKE) / 이메일(LIKE) / 계약상태
**페이징**: 20건/페이지

### 2-2. 고객 등록·수정

**유효성 검사**
- 이메일 중복 불가
- 연락처 형식 검증 (숫자 10~11자리)
- 필수값: 이름 / 연락처 / 이메일 / 주소

**예외 처리**
- 계약이 존재하는 고객 삭제 불가 (비활성화 처리)

### 2-3. 고객 상세 조회

**탭 구성**
- 기본정보 탭: 고객 정보
- 계약 이력 탭: 계약번호 / 상품명 / 계약기간 / 상태
- 청구 이력 탭: 청구월 / 청구금액 / 수납여부 (최근 12건)

---

## 3. 장비 / 상품 관리

### 3-1. 장비 관리

**유효성 검사**
- 장비유형: 공통코드 EQUIPMENT_TYPE 값만 허용
- 모델명 + 제조사 조합 중복 불가

**예외 처리**
- 연결된 상품이 있는 장비 삭제 불가

### 3-2. 상품 관리

**유효성 검사**
- 월 렌탈료: 0 초과
- 기본 계약 기간: 1개월 이상

**예외 처리**
- 진행 중 계약(ACTIVE/SUSPENDED)이 있는 상품 삭제 불가

---

## 4. 계약 관리

### 4-1. 계약 등록

**처리 흐름**
```
고객 선택 (팝업)
  └─▶ 상품 선택 → 월 렌탈료 자동 입력
        └─▶ 계약기간 / 설치주소 입력
              └─▶ 계약 저장 (상태: ACTIVE)
                    └─▶ 방문 배정 화면 이동 유도
```

**유효성 검사**
- 계약 종료일 > 계약 시작일
- 동일 고객 + 동일 상품 중복 계약 불가 (ACTIVE 상태)
- 비활성 상품으로 계약 등록 불가

### 4-2. 계약 해지

**처리 흐름**
```
해지 사유 입력
  └─▶ 계약 상태 → TERMINATED
        └─▶ 미납 청구 존재 시 확인 팝업
              └─▶ 이후 청구 생성 배치에서 제외
```

**유효성 검사**
- 해지 사유 필수 입력
- 이미 TERMINATED 상태인 계약 재해지 불가

## 5. 기사 관리

### 5-1. 방문 배정

**처리 흐름**
```
계약 선택 → 기사 선택 → 방문 예정일 / 방문유형 입력
  └─▶ 방문 배정 저장
        └─▶ Kafka 이벤트 발행 (rental.visit.assigned)
              └─▶ 알림 INSERT
```

**유효성 검사**
- 방문 예정일: 오늘 이후만 허용
- 동일 기사 동일 날짜 5건 초과 배정 시 경고 (강제 등록 가능)

## 6. 청구 관리

### 6-1. 월 청구 일괄 생성 배치

**처리 흐름**
```
1. 멱등성 체크 — 해당 청구월 배치 이미 실행됐는지 확인
     └─▶ 이미 완료 상태면 실행 거부 (오류 응답)

2. 배치 실행 이력 INSERT (상태: RUNNING)

3. 대상 계약 조회
     └─▶ 계약상태 = ACTIVE
     └─▶ 해당 청구월 청구 미생성 건

4. 청구 데이터 bulk INSERT
     └─▶ 납기일: 청구월 말일
     └─▶ 청구금액: 계약의 월 렌탈료

5. 배치 실행 이력 UPDATE
     └─▶ 상태: COMPLETED / 처리건수 기록

6. Kafka 이벤트 발행 (rental.billing.created)

7. 실패 시:
     └─▶ 배치 이력 UPDATE (상태: FAILED)
     └─▶ 처리된 건 롤백
```

**성능 목표**
- 5만 건 기준 처리 시간 측정 및 기록
- 건별 INSERT 대비 bulk INSERT 수치 비교

**유효성 검사**
- 배치 실행은 관리자 수동 실행 또는 스케줄(@Scheduled)
- 동일 청구월 중복 생성 방지 (MERGE 또는 중복 체크)

---

## 7. 수납 관리

### 7-1. 수납 처리

**처리 흐름**
```
청구 건 선택 (UNPAID 또는 OVERDUE만 가능)
  └─▶ 수납금액 / 수납방법 / 수납일 입력
        └─▶ 수납 데이터 INSERT (트랜잭션)
              └─▶ 청구 상태 UPDATE → PAID
                    └─▶ Kafka 이벤트 발행 (rental.payment.completed)
                          └─▶ Consumer: 연체 상태 해제 + 알림 INSERT
```

**유효성 검사**
- PAID / CANCELLED 상태 청구는 수납 불가
- 수납금액: 0 초과
- 수납일: 오늘 이전 날짜만 허용

**예외 처리**
- 수납 INSERT 성공 / 청구 상태 UPDATE 실패 시 전체 롤백

---

## 8. 연체 관리

### 8-1. 연체 상태 전환 배치

**처리 흐름**
```
UNPAID 청구 중 납기일 < 오늘인 건 조회
  └─▶ 청구 상태 UNPAID → OVERDUE 일괄 변경
        └─▶ Kafka 이벤트 발행 (rental.payment.overdue)
              └─▶ Consumer: 알림 INSERT
```

### 8-2. 연체 수동 해제

**유효성 검사**
- 해제 사유 필수 입력
- OVERDUE 상태 건만 수동 해제 가능

---

## 9. 대시보드

### 9-1. 집계 위젯

**처리 흐름**
```
Redis 캐시 조회 (키: dashboard:summary)
  └─▶ 캐시 HIT → 즉시 반환
  └─▶ 캐시 MISS → DB 집계 쿼리 실행 → Redis 저장 (TTL: 5분)
```

**집계 항목**
| 위젯 | 쿼리 대상 |
|---|---|
| 전체 계약 수 | CONTRACT_STATUS = ACTIVE |
| 이번 달 청구 수 | 청구월 = 현재월 |
| 미납 수 / 금액 | BILLING_STATUS = UNPAID 또는 OVERDUE |
| 이번 달 수납액 | 수납일 현재월, BILLING_STATUS = PAID |

**성능 목표**: Redis 캐시 적용으로 집계 쿼리 반복 실행 방지

## 10. 알림 내역

### 10-1. 알림 INSERT (Kafka Consumer)

**처리 흐름**
```
Kafka 이벤트 수신
  └─▶ 알림 유형 / 메시지 생성
        └─▶ 알림 테이블 INSERT
```

**알림 유형별 메시지**
| 유형 | 메시지 예시 |
|---|---|
| BILLING_CREATED | `{청구월} 청구서 {N}건이 생성되었습니다.` |
| PAYMENT_COMPLETED | `{고객명} 님의 {청구월} 수납이 완료되었습니다.` |
| PAYMENT_OVERDUE | `{고객명} 님의 {청구월} 청구가 연체 처리되었습니다.` |
| VISIT_ASSIGNED | `{계약번호} 방문이 {기사명}에게 배정되었습니다.` |

### 10-2. 알림 목록 조회
- 최근 100건 표시
- 읽음 / 미읽음 상태 관리
- 알림 클릭 시 관련 화면으로 이동

## 11. 통계 / 리포트

### 11-1. 엑셀 다운로드 공통

**처리 흐름 (스트리밍)**
```
조회 조건 입력
  └─▶ DB 스트리밍 조회 (Cursor 기반)
        └─▶ Apache POI SXSSFWorkbook으로 행 단위 write
              └─▶ HTTP Response OutputStream으로 flush
```

**예외 처리**
- 조회 건수 0건 시 빈 파일 대신 오류 응답
- 다운로드 중 오류 시 partial file 방지

### 11-2. 미납 현황 엑셀

**쿼리 최적화 대상**
- 고객 + 계약 + 청구 조인 조회
- 서브쿼리 vs JOIN 전환 실행계획(EXPLAIN PLAN) 비교 기록

## 12. 인증

### 12-1. 회원가입

**처리 흐름**
```
이메일 / 비밀번호 / 이름 / 연락처 입력
  └─▶ 이메일 중복 체크
        └─▶ 비밀번호 BCrypt 암호화
              └─▶ 고객 테이블 INSERT
```

**유효성 검사**
- 이메일 형식 검증 + 중복 불가
- 비밀번호: 8자 이상

### 12-2. 로그인 / 로그아웃

**처리 흐름**
```
로그인:
  이메일 / 비밀번호 검증
    └─▶ Access Token (30분) + Refresh Token (7일) 발급
          └─▶ Refresh Token → Redis 저장

로그아웃:
  Redis에서 Refresh Token 삭제 → 토큰 무효화
```

**예외 처리**
- 5회 연속 로그인 실패 시 계정 잠금 (30분)

## 13. 사용자 (고객 포털)

### 13-1. 카드 납부

**처리 흐름**
```
미납 청구 선택
  └─▶ Toss Payments 결제 위젯 호출
        └─▶ 결제 완료
              └─▶ 백엔드 결제 검증 API 호출 (Toss 서버 검증)
                    └─▶ 수납 처리 (트랜잭션)
                          └─▶ Kafka 이벤트 발행 (rental.payment.completed)
```

**예외 처리**
- 결제 완료 후 백엔드 검증 실패 시 → Toss 결제 취소 API 호출
- 결제 중복 방지: 동일 청구 건 결제 진행 중 상태 관리 (Redis)
