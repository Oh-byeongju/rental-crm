    - `BillingCreateService` — `@Transactional` 제거. dispatcher 만. batchLog 작업은 `BatchLogManager` 위임.
    - `SingleSaveStrategy` / `ChunkFlushClearStrategy` / `BulkJdbcStrategy` — 각자 메서드 level `@Transactional` 추가 (자체 tx 시작).
    - `ChunkCommitStrategy` 신규 — `TransactionTemplate.execute(REQUIRES_NEW)` 로 1000건 chunk 마다 commit.
  - **R4 결과 = 27,876 ms** (R1 의 4.3배 느림). 원인: LGWR 50회 commit 비용 (redo log flush 디스크 I/O). 학습: chunk commit 의 진짜 가치는 성능 X — UNDO 부담 ↓ / 잠금 시간 ↓ / 재시작 친화 / 메모리 안정. R5 (UNDO 폭주) 에서 진가.
  - **BatchLogManager 검증** — R4 의 BL_BATCH_LOG STATUS=COMPLETED, PROCESS=50000, BATCH_PARAMS 정상. detached batchLog 버그 본질 해결.
  - **순수 성능 순위 (4 라운드)** — R1 (6.5초) < R3 (16.2초) < R2 (21.5초) < R4 (27.9초). 한 tx 가 항상 가장 빠름.
  - **리포트** — [`docs/perf-reports/2026-05-13-billing-create-r1-r2-r3-r4.md`](perf-reports/2026-05-13-billing-create-r1-r2-r3-r4.md)
